# สิ่งที่ต้องทำที่ตัวอุปกรณ์ DVR/NVR

**วัดค่าเมื่อ:** 2026-11-07 บนระบบ Dev อ่านจากเครื่องจริงแบบอ่านอย่างเดียว ระบบนี้ไม่เคยเปลี่ยนค่าในเครื่อง ทุกข้อต้องทำที่ตัวเครื่องเอง

ชื่อเมนูในเอกสารนี้เป็นของหน้าเว็บ Hikvision โดยทั่วไป อาจต่างกันตามรุ่นและเฟิร์มแวร์ ยังไม่ได้เทียบกับเครื่องจริง

รุ่นในตารางอ่านจากตัวเครื่อง ส่วนค่ารุ่นในหน้าอุปกรณ์ของระบบยังผิดอยู่ 2 เครื่อง (MD บันทึกเป็น DS-7716NXI-K4(D), แผนกบุคคลบันทึกเป็น DS-7208HQHI-K1) ควรแก้ในหน้าอุปกรณ์

| เครื่อง | IP | รุ่นจริง | เฟิร์มแวร์ |
|---|---|---|---|
| DVR แผนกสโตร์ | 192.168.30.203 | DS-7208HQHI-K1 | V4.21.002 |
| MD | 192.168.20.201 | iDS-7216HQHI-M2/S | V4.28.000 |
| NVR EOE | 192.168.20.220 | DS-7716NXI-K4(D) | V4.84.035 |
| แผนกบุคคล ห้องสัมภาษณ์ | 192.168.20.213 | DS-7216HQHI-K2 | V4.20.000 |

## ควรทำก่อน

### 1. [ ] ตรวจว่าเครื่องบันทึกลง HDD จริงและดิสก์ปกติ (ทุกเครื่อง)

- **ทำอะไร:** ดูสถานะ HDD ว่าปกติ, ตารางบันทึกเป็นบันทึกต่อเนื่องตามที่ต้องการ, เปิดบันทึกทับเมื่อดิสก์เต็ม และดูว่าเก็บย้อนหลังได้กี่วัน
- **เมนู:** Configuration > Storage
- **เหตุผล:** ระบบเราไม่ได้เก็บวิดีโอไว้เอง HDD ของเครื่องคือหลักฐานชุดเดียว ถ้าดิสก์เสียหรือตารางบันทึกผิด จะไม่มีภาพย้อนหลังให้ดูหรือตัดคลิป และระบบเรายังไม่ได้แจ้งเตือนเรื่อง HDD เสีย
- **ยังต้องดูที่เครื่อง:** เก็บย้อนหลังได้กี่วัน และเปิดบันทึกทับอยู่หรือไม่ ส่วนอื่นอ่านจากเครื่องแล้วตามตารางนี้

| เครื่อง | HDD | สถานะ | ว่าง | SMART ลูกที่ 1 | อุณหภูมิ | เปิดใช้งานมาแล้ว |
|---|---|---|---|---|---|---|
| DVR แผนกสโตร์ | 1 ลูก 2 TB | ok | 0 | ok | 37°C | 3,285 วัน (ราว 9 ปี) |
| MD | 1 ลูก 4 TB | ok | 0 | ok | 40°C | 1,462 วัน (ราว 4 ปี) |
| NVR EOE | 3 ลูก ลูกละ 12 TB | ok, idle, ok | ลูกที่ 1 และ 2 ว่างเกือบหมด, ลูกที่ 3 ว่าง 8.2 TB จาก 11.4 TB | ok | 40°C | 45 วัน |
| แผนกบุคคล ห้องสัมภาษณ์ | 1 ลูก 2 TB | ok | 0 | ok | 37°C | 2,453 วัน (ราว 7 ปี) |

- **ว่าง 0 ไม่ได้แปลว่าเสีย:** เครื่องที่บันทึกทับจะเต็มตลอดและยังมีภาพเมื่อวาน แต่ควรดูว่าเก็บย้อนหลังได้กี่วัน
- **อายุดิสก์:** ถ้าค่าวันเปิดใช้งานตรงจริง HDD ของ DVR แผนกสโตร์และแผนกบุคคลใช้งานมานาน ควรวางแผนเปลี่ยนก่อนเสีย
- **ตารางบันทึก:** ทุกช่องที่ใช้ตั้งบันทึกต่อเนื่อง 7 วัน ช่อง IP (NVR EOE Ch 1–3, แผนกบุคคล Ch 17–21) แจ้ง `Enable=false` แต่ตรวจแล้วมีภาพเต็มวันของ 2026-11-06 ไม่มีช่วงขาด จึงไม่น่าใช่ปัญหา

### 2. [ ] ตั้งเวลาเครื่องให้ตรงด้วย NTP (ทุกเครื่อง)

- **ทำอะไร:** ตั้ง Time Zone เป็น GMT+07:00 เปิด NTP และชี้ไปที่ NTP ในองค์กร หรือ `pool.ntp.org` ถ้าเครื่องออกอินเทอร์เน็ตได้ ซิงก์ทุก 60 นาที
- **เมนู:** Configuration > System > System Settings > Time Settings
- **เหตุผล:** เวลาที่ค้นย้อนหลังคือเวลาของเครื่อง ถ้าเครื่องเวลาไม่ตรงกัน เวลาเดียวกันจะเป็นคนละเหตุการณ์ข้ามเครื่อง และเวลาในคลิปหลักฐานจะคลาดจากเวลาจริง

| เครื่อง | เวลาปัจจุบันเทียบกับ Server |
|---|---|
| DVR แผนกสโตร์ | เร็ว 3 นาที 21 วินาที |
| MD | ช้า 8 นาที 5 วินาที |
| NVR EOE | เร็ว 7 นาที 39 วินาที |
| แผนกบุคคล ห้องสัมภาษณ์ | ช้า 11 นาที 20 วินาที |

### 3. [ ] ตั้ง I-Frame Interval ของ MD (ทุกช่องที่ใช้)

- **ทำอะไร:** ตั้ง I Frame Interval เป็น 1–2 เท่าของ FPS เช่น FPS 25 ตั้ง 25–50 ทั้ง Main-stream และ Sub-stream ถ้าเปิด H.265+ อยู่และค่านี้ปรับไม่ได้ ให้ปิด H.265+ แล้วลองใหม่
- **เมนู:** Configuration > Video/Audio > Video
- **เหตุผล:** เป็นข้อที่เห็นผลชัดที่สุดกับ MD
  - **เปิดภาพช้า:** ภาพเริ่มเล่นได้ต้องรอ I-Frame วัดได้ภาพแรกนานถึง 10.5 วินาที และเคยจอดำเกือบ 20 วินาที
  - **เล่นเร็วไม่ลื่น:** ที่ 8x ได้ 0.4 ภาพต่อวินาที และ 16x ได้ 0.8 ภาพต่อวินาที เทียบกับ DVR ที่ได้ 8 และ 16
- **ค่าปัจจุบัน:** MD ห่างประมาณ 19 วินาที, NVR EOE 2 วินาที, DVR แผนกสโตร์และแผนกบุคคล 1 วินาที
- **ข้อแลกเปลี่ยน:** ไฟล์บน HDD ใหญ่ขึ้นบ้าง จึงเก็บย้อนหลังได้สั้นลง ภาพที่บันทึกไว้ก่อนหน้าไม่เปลี่ยน
- **ยังไม่ได้พิสูจน์:** H.265+ เป็นสาเหตุหรือไม่ ผมสันนิษฐานจากระยะที่ห่างผิดปกติ

### 4. [ ] แก้หรือเอาช่องที่ไม่มีสัญญาณภาพออก

- **ทำอะไร:** ตรวจกล้อง สาย และไฟของช่องด้านล่าง ถ้าไม่ได้ใช้แล้ว ให้เอาเครื่องหมายช่องนั้นออกที่หน้าอุปกรณ์ในระบบ หรือตั้งระดับเป็น "ไม่แจ้งเตือน"
- **เหตุผล:** ช่องเหล่านี้ทำให้จำนวนออฟไลน์สูงกว่าปัญหาจริง และบังกล้องที่เสียจริงจากสายตา
- **ช่องที่ไม่มีสัญญาณตอนนี้:** DVR แผนกสโตร์ Ch 2, MD Ch 4, 6, 9, 12, 16 และแผนกบุคคล Ch 11
- **ตรวจเพิ่ม:** แผนกบุคคล Ch 12 หลุดซ้ำ 6 ครั้งในวันที่ 7 พ.ย. น่าจะเป็นสาย หัวต่อ หรือไฟ

### 5. [ ] เปลี่ยนรหัสผ่านอุปกรณ์ทั้ง 4 เครื่อง

- **ทำอะไร:** เปลี่ยนรหัสที่ตัวเครื่อง แล้วกรอกรหัสใหม่ในหน้าอุปกรณ์ของระบบทันที ถ้าทำได้ ให้สร้างบัญชีแยกสำหรับระบบนี้ มีสิทธิ์แค่ดูสดและดูย้อนหลัง
- **เหตุผล:** รหัสปัจจุบันเคยถูกวางในแชตทำงาน บัญชีแยกช่วยจำกัดความเสียหายถ้ารหัสรั่ว และหลีกเลี่ยงการใช้ admin
- **ข้อควรระวัง:** ถ้าเปลี่ยนที่เครื่องแล้วไม่แก้ในระบบ ระบบจะล็อกอินผิดซ้ำ และเครื่องอาจล็อกบัญชีได้
- **ต้องทดสอบหลังตั้งบัญชีแยก:** ดูสด, ดูย้อนหลัง, ตัดคลิป และการตรวจ NO VIDEO ยังไม่ได้ลองกับบัญชีสิทธิ์จำกัด

### 6. [ ] ล็อก IP ของเครื่อง

- **ทำอะไร:** ตั้ง IP แบบ Static หรือจอง IP ไว้ที่ DHCP
- **เหตุผล:** ระบบเชื่อมต่อเครื่องด้วย IP ที่บันทึกไว้ ถ้า IP เปลี่ยน ทุกช่องของเครื่องจะหลุดพร้อมกัน แม้เครื่องยังทำงานปกติ

## ควรทำเมื่อมีเวลา

### 7. [ ] ลด FPS ของ Sub-stream เป็น 15 (NVR EOE ก่อน)

- **ทำอะไร:** ตั้ง Sub-stream เป็น 15 FPS โดยไม่ต้องแก้ Main-stream และตั้ง I Frame Interval เป็น 15–30
- **เมนู:** Configuration > Video/Audio > Video > Sub-stream
- **เหตุผล:** ห้องภาพสดเปิดพร้อมกันได้ถึง 16 ช่อง การลดเฟรมลดภาระเครือข่ายและเบราว์เซอร์ และการดูเฝ้าระวังยังเห็นเหตุการณ์ครบ
- **ค่าปัจจุบัน:** Sub-stream ที่เคยตรวจ 10 กล้องตั้ง 25 FPS NVR EOE เฟรมตก 3–4% ในการทดสอบ 30 นาที ส่วน DVR และ MD แทบไม่ตก
- **ยังไม่ได้พิสูจน์:** ลดแล้วเฟรมตกจะหายหรือไม่ และยังไม่ได้วัดกับช่องอื่น

### 8. [ ] ตรวจสาเหตุที่ NVR EOE ส่งย้อนหลังได้ช้า

- **ทำอะไร:** ดู HDD Status และภาระเครื่อง รวมถึงเครือข่ายและการเชื่อมต่อเครื่องนี้ ดูว่ามีใครกำลังดูหรือดาวน์โหลดจากเครื่องอยู่ไหม
- **เหตุผล:** เล่นเร็วได้จริงแค่ประมาณ 4–5x ขณะที่อีก 3 เครื่องส่งได้ถึง 16x
- **ยังไม่ได้พิสูจน์:** ยังไม่ทราบสาเหตุ NVR EOE เป็นรุ่นเดียวในกลุ่มนี้ที่เป็น NVR จึงอาจเป็นข้อจำกัดของรุ่น หรืออาจเกี่ยวกับปริมาณข้อมูลที่สูงกว่า (2.12 Mbps ที่ 1x) สถานะ HDD ลูกที่ 1 และ SMART รายงานว่าปกติ

### 9. [ ] ตรวจ DVR แผนกสโตร์ Ch 4

- **ทำอะไร:** ดูภาพที่หน้างานและเข้าเมนูของกล้องตัวนี้
- **เหตุผล:** ภาพมีข้อความ `VERSION / VIDEO OUT` ค้างอยู่ คล้ายเมนูของตัวกล้องที่เปิดค้าง ข้อความนี้บังภาพและจะติดไปในหลักฐาน

## ไม่ต้องทำ

| เรื่อง | เหตุผล |
|---|---|
| เปลี่ยน Sub-stream ของ MD และ NVR EOE เป็น H.264 | ยอมรับ H.265 เป็นข้อยกเว้นแล้วเมื่อ 2026-11-07 เปิดภาพสดบนเครื่อง Dev ได้ ทำเมื่อเจอเครื่องที่เปิดไม่ได้เท่านั้น |
| เปลี่ยน Main-stream เป็น H.264 | H.265 ประหยัด HDD และใช้งานได้ |
| เปลี่ยนเสียง G.711 เป็น AAC | ระบบใช้เฝ้าดูภาพเป็นหลัก ตัดคลิปแปลงเสียงให้อยู่แล้ว |

## หลังทำเสร็จ

แจ้งผมว่าทำข้อไหนแล้ว ผมจะวัดซ้ำแบบอ่านอย่างเดียว ได้แก่เวลาเครื่อง, ระยะ I-Frame, ความเร็วเล่นย้อนหลัง และเวลาเปิดภาพแรก แล้วอัปเดตเอกสารนี้
