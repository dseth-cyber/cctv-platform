### ถอดสายแลน IT-SERVER-001 หลังแก้ไข (2026-11-07, เวลาไทย)

จับเวลาด้วย ping วินาทีละครั้ง โดยเกณฑ์เดิม 3 วินาทีถูกแทนด้วยเกณฑ์ที่อนุมัติ เพราะกล้องที่ไม่มีคนดูไม่มีสตรีมให้จับการหลุด และการลดเวลารอสัญญาณของ MediaMTX เสี่ยงตัดภาพเมื่อเครือข่ายสะดุด

| รอบ | ping ตอบครั้งสุดท้าย | `offline` และแจ้งเตือน critical | ping กลับมา | `online` | ระบบรายงาน downtime / ping หายจริง |
|---|---|---|---|---|---|
| 1: มีคนดู | 08:22:42 | 08:22:56 (14.2 วินาที) | 08:25:16 | 08:27:00 (1 นาที 44 วินาที) | 4 นาที 0 วินาที / 2 นาที 34 วินาที |
| 2: ไม่มีคนดู | 08:31:05 | 08:33:03 (1 นาที 58 วินาที) | 08:42:10 | 08:44:00 (ไม่เกิน 1 นาที 51 วินาที) | 12 นาที 0 วินาที / 11 นาที 5 วินาที |

รอบ 2 เกิดแจ้งเตือน critical ใหม่ ทั้งที่แจ้งเตือน `Camera online` ของรอบ 1 ยังเปิดอยู่ แสดงว่าแจ้งเตือนชนิดข้อมูลไม่บังการหลุดซ้ำแล้ว

**สิ่งที่แก้:**
- เมื่อสตรีม on-demand ปิด API จะตรวจพอร์ตกล้องทันที ถ้าติดต่อไม่ได้จึงแจ้ง `offline`
- เปลี่ยน `camera_offline_threshold_minutes` จาก 5 เป็น 2 นาที
- รอบตรวจไม่เปลี่ยนกล้องที่ยังติดต่อไม่ได้เป็น `recovering` หรือ `online` อีก
- แจ้งเตือน `Camera online` และ `Camera created` ไม่บังแจ้งเตือนกล้องหลุด
- เหตุการณ์ที่ตรวจพบจาก webhook ถูกปิดโดยรอบตรวจได้
- ช่องภาพขึ้นแถบ "กล้องออฟไลน์" เมื่อสถานะเป็น `offline`

**ยังไม่ได้พิสูจน์:**
- ทดสอบกับกล้องเดี่ยวตัวเดียว ยังไม่ได้ทดสอบช่องของ DVR/NVR
- แถบ "กล้องออฟไลน์" ทดสอบโดยแก้คำตอบ API ในเบราว์เซอร์ ยังไม่ได้เห็นระหว่างถอดสายจริง
- การนับ downtime จากเวลาที่ webhook พบการหลุด แก้หลังการทดสอบ 2 รอบนี้ และมีเฉพาะ unit test
- ยังไม่ได้ตรวจว่าภาพในช่องกลับมาเองหลังกล้องกลับมา ถ้าไม่กลับมาให้กดปุ่มลองใหม่

**พฤติกรรมที่ควรรู้:** Downtime ละเอียดประมาณ 1 นาทีตามรอบตรวจ และถ้ากล้องเดิมหลุดครั้งที่ 3 ภายใน 15 นาที ระบบจะไม่ออกแจ้งเตือนใหม่ แต่บันทึกเป็น flapping

## ข้อจำกัดที่ยังอยู่

1. **MD ส่ง keyframe ห่างประมาณ 19 วินาที** (NVR EOE ~2 วินาที, DVR ~1 วินาที) วัดจาก Ch1 และ Ch2 ทำให้:
   - ย้อนหลังอาจจอดำได้ถึง ~20 วินาทีก่อนภาพขึ้น เมื่อ WebRTC พลาด keyframe แรก
   - ภาพเริ่มจาก keyframe ก่อนเวลาที่ขอ เวลาบนหน้าเว็บจึงอาจนำภาพอยู่ถึงหนึ่งช่วง keyframe (พบ 6 และ 12 วินาที) จึงเปลี่ยนข้อความในหน้าให้ยึดเวลาบนภาพเป็นหลัก
   - **คลิปจาก MD อาจขาดช่วงท้ายได้** เพราะอาจเริ่มก่อนเวลาที่ขอแต่ความยาวเท่าเดิม ข้อนี้อนุมานจากพฤติกรรมข้างต้น ยังไม่ได้ทดสอบโดยตรง
   - วิธีแก้ที่ตรงจุด: ตั้ง I-Frame Interval ที่ MD เป็น 1–2 เท่าของ FPS ตาม runbook แล้วทดสอบซ้ำ
2. **นาฬิกาเครื่องไม่ตรง:** DVR เร็ว 3 นาที 22 วินาที, NVR EOE เร็ว 7 นาที 41 วินาที, MD ช้า 8 นาที 2 วินาที (ระบบเทียบให้แล้ว แต่ควรตั้ง NTP)
3. **เสียงยังไม่ได้ทดสอบ:** DVR และ MD ใช้ G.711
4. **เฟรมตก 3–4% บน NVR EOE** วัดจาก headless Chrome เครื่องเดียว ยังไม่รู้สาเหตุ และภาพไม่ค้าง
5. **DVR Ch4 แสดงข้อความ `VERSION / VIDEO OUT`** ค้างบนภาพ คล้ายเมนูของตัวกล้อง ควรตรวจหน้างาน
6. **`/health` ตอบช้า 3.4–5 วินาที** เพราะรอ SeaweedFS ที่ไม่ได้เปิดบนเครื่อง Dev (timeout 5 วินาที) API อื่นตอบ 5–17ms แต่วัดหลังจบการทดสอบ ไม่ได้วัดระหว่างเปิดภาพ 10 ตัว
7. **แจ้งเตือนซ้ำ:** `Emergency FIFO Eviction Triggered` ขึ้นทุกรอบตรวจ สะสม 81 รายการ เพราะดิสก์ค้างที่ 93%
